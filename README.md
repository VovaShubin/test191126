# Keitaro Wrapper

Создаёт стандартные кампании Keitaro и редактирует офферы в существующих
потоках. Интерфейс поддерживает локальные черновики, архив удалённых офферов,
отмену изменений, публикацию и закрепление весов.

## Установка и запуск

Требуется Python 3.11+.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

Заполните `.env`:

- `KEITARO_BASE_URL` — адрес трекера без `/admin`;
- `KEITARO_API_KEY` — ключ из **Профиль → API ключи**;
- `KEITARO_DOMAIN_ID`, `KEITARO_GROUP_ID`, `KEITARO_TRAFFIC_SOURCE_ID` —
  ID обязательных настроек создаваемой кампании;
- `CAMPAIGN_PREFIX` — обязательный тестовый префикс с фамилией;
- `DATABASE_URL` — URL локальной БД (по умолчанию SQLite).

Примените миграции и запустите сервер:

```powershell
alembic upgrade head
uvicorn app.main:app --reload
```

Интерфейс откроется на <http://127.0.0.1:8000>.

## Тестовая кампания

Кампании создаются в самом Keitaro, а не только в локальной БД. Для создания
одной демонстрационной кампании выполните после миграций:

```powershell
python -m app.seed
```

Параметры берутся из `SEED_CAMPAIGN_NAME`, `SEED_GEO` и `SEED_OFFER_ID` в
`.env`. Сидер идемпотентен: повторный запуск найдёт кампанию по полному имени,
не создаст дубль и обновит её локальный снимок.

## Миграции

Текущая схема:

```powershell
alembic current
alembic history
```

После изменения SQLAlchemy-моделей создайте и проверьте новую миграцию:

```powershell
alembic revision --autogenerate -m "описание изменения"
alembic upgrade head
```

Откатить последнюю миграцию:

```powershell
alembic downgrade -1
```

Перед откатом на рабочей БД сделайте резервную копию. Миграция `20261125_01`
создаёт таблицы `campaigns`, `streams` и `stream_offers`.

## Логика редактора

1. **Fetch streams** получает актуальные потоки и офферы из Keitaro. Потоки без
   офферов показываются без попытки разобрать их редиректы и фильтры.
2. Добавление, Remove, Bring back и pin меняют только локальный черновик.
3. Незакреплённые веса делят остаток после закреплённых и всегда дают ровно
   100%; целочисленный остаток распределяется по возрастанию ID оффера.
4. **Cancel** возвращает последний опубликованный/загруженный снимок.
5. **Push to KT** отправляет активные офферы в Keitaro. Удалённые остаются
   локально в архиве и могут быть возвращены.
6. Повторный Fetch помечает офферы, удалённые непосредственно в Keitaro, как
   архивные вместо физического удаления из локальной БД.
